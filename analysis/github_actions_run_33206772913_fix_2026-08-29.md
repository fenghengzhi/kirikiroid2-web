# GitHub Actions run 33206772913 failure correction

## Observed failures

The run contained two independent failures after commit `e80398a2`:

1. `adb-frida` job `98969852903` successfully booted Redroid, loaded the
   harness, and recorded the normalized motion oracle. It then failed in
   `Record motion_playback render-stage oracle` because the workflow requested
   seven stages that the Kirikiroid2 1.3.9 agent intentionally rejects.
2. The `wasmtime` job recorded all 63 `yuzulogo` frames, then failed while
   decoding `m2logo` render-probe JSONL. A non-finite floating-point value from
   a diagnostic render array was emitted as a non-JSON token by the C++ array
   serializer.

## Regression source

Run `32971807749` at `5cc45b36` confirms that the same `adb-frida` environment
passes when it records only `trace_flatten`. Commit `c85306fc` had already
changed `frida_motion_stage_agent.js` to the 1.3.9 oracle and documented that
the retained render-stage offsets belong to the retired 1.4.4 lane.

Commit `6a366f37` later reintroduced `run_motion_stage_oracle.py --stage
render_path` into the active workflow without rebasing those offsets. The agent
therefore failed closed with:

```text
Kirikiroid2 1.3.9 oracle supports only trace_flatten; unrebased stages requested
```

This was a workflow-capability regression, not a Redroid, ADB, Frida, APK, or
harness failure.

## Correction

- Restore the active Android job to its supported `trace_flatten` recording and
  artifact upload.
- Compare only normalized Wasmtime/Android playback traces in the active paired
  compare job.
- Keep Wasmtime render-stage output as a one-sided diagnostic artifact; do not
  present it as paired Android evidence.
- Serialize non-finite Wasmtime diagnostic array members as JSON `null` while
  preserving the existing finite-value precision.
- Include a bounded source fragment in future render JSON decode errors.
- Correct the MP-V05 analysis entries that previously called the unexecutable
  paired render workflow active/implemented.

Re-enabling paired render-step or draw-dispatch comparison requires a separate
four-binary/1.3.9 offset-rebase task; old 1.4.4 offsets must not be enabled just
to make CI produce an artifact.
