## Android 归属与 fresh 证据

本轮 fresh 调用 IDA MCP `decompile(addr="0x42CF28")`。IDA 给出的函数范围是
`0x42CF28..0x42CF9C`（30 条指令）；`xrefs_to(0x42CF28)` 只返回
`.init_array` 数据引用 `0x19EA090`，相邻 `0x19EA088` 项为 `0x42CEF8`。
`callees(0x42CF28)` 返回空集，因此该入口没有直接调用注册 callback。

fresh decompile/disasm 的关键写入如下：

- `0x42CF74`：第一只对象写入 vptr address-point `0x1A0B578` 与
  `L"PSBFile.dll"`；`0x42CF90` 再写旧 ClassRegist 链头和
  `L"PSBFile"`。
- `0x42CF78`：第二只对象写入 vptr address-point `0x19FD8E8` 与同一模块名；
  `0x42CF80` 写入 `{ init=@59849C, term=null }`，`0x42CF94` 写旧
  PreRegist 链头。
- `0x42CF98`：一次 128-bit store 把两只新对象分别设为 PreRegist、
  ClassRegist 新链头；PostRegist 头不变。
- vtable 原始槽值：`[0x1A0B578,0x1A0B580] =
  [0x59A8D8,0x59A968]`。callback vtable 的两槽是
  `[0x529018,0x529028]`；仅作上下文 fresh decompile 后可见，前者只在
  `this+24` 非空时调用 init，后者只在 `this+32` 非空时调用 term。

因此该入口属于 NCB 静态 autoreg 链构造：第一只为 PSBFile typed-class
autoreg，第二只为 pre-register callback autoreg。`0x59849C` 只是被保存为
函数指针；`0x59A8D8`/`0x59A968` 只是 class-autoreg vtable 成员，均在后续
模块注册/反注册流程中经 vdispatch 执行，不是 `0x42CF28` 的 direct callee。

## Android 伪代码（8 行）

```text
oldPre = _top[PreRegist]; oldClass = _top[ClassRegist]
classObj.vptr = classAutoregVtable
classObj = { module=L"PSBFile.dll", next=oldClass, name=L"PSBFile" }
preObj.vptr = callbackAutoregVtable
preObj = { module=L"PSBFile.dll", next=oldPre, init=@59849C, term=null }
_top[PreRegist] = &preObj; _top[ClassRegist] = &classObj
// _top[PostRegist] 不变；本入口无分支、无 direct call、无堆分配
// 无失败/异常路径；由 .init_array 一次性执行，返回 void
```

## 总判定

`ALIGNED`

确定 GAP：无。

证据边界：stripped/O3 二进制不能证明原始宏的文本拼写。旧 Hex-Rays `__n128` 返回型
是合并 store 后的 Q0 残留；2026-08-02 已按 `.init_array` ABI 纠正为 `void(void)`，
复反编译不再显示向量返回。这不形成生产行为差异。
