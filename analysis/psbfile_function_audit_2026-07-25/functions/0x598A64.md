## Android 关键伪代码（10 行）

```text
Transfer_guess(source, hidden_result):
  owner = source.owner                         // source/result 均无 null guard
  hidden_result.owner = owner                  // 默认直接复制，不先 AddRef
  if owner != null and owner.refCount == 0:
    raw = *(owner.data - 8); if raw != null: operator_delete_array(raw) // data==null 先 fault
    operator_delete(owner)
  source.owner = null                          // 仅所有正常返回分支执行
  return hidden_result                         // zero-ref + dealloc 正常才可能返回 dangling result
  if inline cleanup throws: terminate           // callee 内部 landing；不是接口 noexcept 证明
  caller call edge is unwind-capable            // 清既有 locals；不析构未完成的 hidden_result
```

函数没有成功/失败状态、重试或异常恢复。对正常有效 holder（refcount `>=1`），返回 holder
取得同一 owner 且计数保持不变，source 被消费为空；空 source 返回空 holder。非法的
incoming-zero owner 只有在 `data` 非空且 aligned dealloc 正常返回、继而 owner delete
执行时才形成 dangling hidden-result；若 `data==null`，虽然 result pointer 已先写入隐藏
槽，但 `data-8` 读取会先 fault，owner 未删、source 未清且没有已完成构造的返回对象。

## 总判定

`EVIDENCE_LIMITED`

Android 当前可证明的数据流、唯一目标调用点、对象转移生命周期、zero-ref/data-null
first-fault 边界及 caller/callee 两层 EH 路径现已与本地实现一致；caller EH 还明确证明
异常 call 不析构未完成的 hidden-sret。iOS arm64 支持 copy/AddRef、共享 Release 与

member/free 身份与 exact special-member 源码 token；不能把 shape 一致误报为原始 C++
拼写已被唯一证明。
