## Android vtable / NCB / 调用链归属

`0x5999F4` 是 Android `PSBMedia` vtable `0x1A0B510` 的 slot 9，接口语义为
storage media 的 `GetListAt`。它不是 NCB typed wrapper，也没有 NCB 成员注册入口；
canonical parent `0x59849C` 负责构造并注册带该 vtable 的进程期 `PSBMedia`，所以
TASK_TREE 边是 `[vtable-member]`，不能伪装成 `0x59849C -> 0x5999F4` 的直接调用。

本函数保留的直接业务调用为 `0x599E04`（EnsureContainer）、`0x59A4B0`
（Resolve）和 Dictionary 分支的 `0x597B1C`（DecodeName）。对 lister 的两处
`Add` 是 vslot 0 间接调用（`0x599BA4`、`0x599C50`），不是 psbfile 函数树中的
另一条直接函数边。

同谱系 iOS arm64 独立保留 Android O3 消除的源码调用分层：vslot 9
`GetListAt@0x1000EE4BC` 在 `0x1000EE50C` 调 classifier `0x1000EBD9C`，Dictionary
分支在 `0x1000EE560/0x1000EE570` 两次调用 packed-view constructor
`0x1000EE0C4`；第二只 record 完全不再读取，后续只消费第一只 record 的
`sp+0x24/+0x28/+0x30`。这给出“key string → 第一只 key view → 第二只
未消费 value-offset view → key loop”的正证据；Android 本体仍独立约束所有 tag、默认值、
循环与 cleanup，iOS 不替代目标行为权威。
